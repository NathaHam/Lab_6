# SplitSmart — Final Logical Data Model

**Status**: Final design package. Human review required.
**This is a logical model.** The database vendor is not selected (HD-11, OD-23). Vendor-specific DDL, column widths, decimal precision and index syntax are written only after OD-23 and OD-03. The capabilities a store must provide are listed in §8.

## 1. Logical types

| Type | Meaning |
|---|---|
| `id` | Opaque unique identifier (generated by `IdGenerator`) |
| `money` | Exact decimal mapped to `BigDecimal`, always at the group currency's minor-unit scale. Alternatively, integer minor units (choice in OD-23). Width is set by approved amount bounds (OD-03). Never floating point. |
| `pct` | Exact decimal with scale ≤ the configured `PercentagePolicy.maxScale` (OD-04) |
| `date` | Calendar date, no time zone |
| `instant` | UTC timestamp |
| `text`, `int`, `long`, `bool`, `bytes` | Usual meanings. Lengths are set in the vendor schema. |
| `version` | Integer used for optimistic versioning |

## 2. Value objects (stored as columns, validated in the domain)

`UserId`, `GroupId`, `ExpenseId`, `PaymentId`, `InvitationId`, `NotificationId`, `CommandId`, `ReceiptKey` → `id`. `Money` → `money` + `currency_code`. `CurrencyUnit` → `currency_code` + `currency_minor_digits` (snapshot taken when the group is created). `Percentage` → `pct`. `EmailAddress` → `email_normalized` + `email_display`. `ParticipantName` → `participant_name_snapshot`. `DateRange` is a query parameter only.

## 3. Entities and relationships

```
UserAccount 1─1 MfaEnrollment, 1─* RecoveryCode, 1─* Session, 1─* EmailVerificationToken
Group 1─* Membership *─1 UserAccount;  Group 1─* Invitation;  Group 1─1 LedgerHead
Group 1─* Expense 1─* ExpenseShare;  Expense 0..1 ReviewerAssignment;  Expense 0..1 ReviewRecord (MVP)
Expense 0..1─1 ReceiptUpload
Group 1─* Payment;  Group 1─* LedgerEntry (source → Expense | Payment)
Expense 1─* Notification 0..1─1 EmailOutboxMessage
ProcessedCommand, AuditRecord (cross-cutting)
[optional] Group 1─* PairBalance (projection, OD-22)
```

## 4. Tables (logical)

### Accounts and security

| Table | Key columns | Constraints and invariants |
|---|---|---|
| `user_account` | id, email_normalized, email_display, display_name, password_hash, status, email_verified_at, created_at, version | **UNIQUE**(email_normalized). `status = ACTIVE` ⇒ verified, MFA confirmed and codes issued. |
| `mfa_enrollment` | user_id PK, secret_ciphertext, key_id, confirmed_at, last_accepted_step | The secret is stored only encrypted. `last_accepted_step` is updated by CAS (replay check). |
| `recovery_code` | id, user_id, batch_id, code_verifier, used_at, invalidated_at | One use: consumed by `UPDATE … WHERE used_at IS NULL AND invalidated_at IS NULL` |
| `email_verification_token` | token_hash PK, user_id, expires_at, used_at | Stored only as a hash. Single use. |
| `session` | token_hash PK, user_id, level (PARTIAL/FULL), created_at, last_seen_at, idle_expires_at, absolute_expires_at, revoked_at | Index (user_id, level, revoked_at, idle_expires_at). Used by the FR-007 signed-out test. |

### Groups

| Table | Key columns | Constraints |
|---|---|---|
| `app_group` | id, name, currency_code, currency_minor_digits, default_reviewer_id NULL, created_by, created_at, version | The currency cannot change. `default_reviewer_id` is a **prefill only** (HD-06). |
| `membership` | id, group_id, user_id, role, joined_at, removed_at NULL, removed_by | **UNIQUE**(group_id, user_id) among active rows. At least one active MANAGER (domain-enforced). |
| `invitation` | id, group_id, invitee_email_normalized, invited_by, status, created_at, decided_at, accepted_user_id | **UNIQUE**(group_id, invitee_email_normalized) among PENDING rows |

### Expenses and review

| Table | Key columns | Constraints |
|---|---|---|
| `expense` | id, group_id, submitter_id, payer_id, amount money, currency_code, expense_date, description, split_method, status, submitted_at, decided_at NULL, supersedes_expense_id NULL (reserved, OD-09), version | amount ≥ 0. currency = group currency. `decided_at` is NOT NULL iff status ≠ PENDING_REVIEW. |
| `expense_share` | (expense_id, participant_id) PK, participant_name_snapshot, percentage pct NULL, share_amount money, allocation_rank, received_extra_unit | share ≥ 0. Σ share = expense.amount. PERCENTAGE ⇒ Σ percentage = 100 and each ≥ 0. At least one row. |
| `reviewer_assignment` | expense_id PK, reviewer_id, assigned_by, assigned_at, version | CHECK reviewer ≠ expense.submitter (domain + DB where supported). assigned_by is a manager. |
| `review_record` | id, expense_id, level, reviewer_id, decision, reason NULL, decided_at | **UNIQUE**(expense_id, level). The MVP always writes level = 1. Immutable. |
| `receipt_upload` | receipt_key PK, uploader_id, group_id, media_type, size_bytes, created_at, expense_id NULL | **UNIQUE**(expense_id) when not null (one receipt per expense) |

Re-designations (OD-10) overwrite `reviewer_assignment` under its version. The history is kept in `audit_record`.

### Ledger and payments

| Table | Key columns | Constraints |
|---|---|---|
| `ledger_head` | group_id PK, sequence long, version | Bumped by every ledger write and every membership removal. Serialization point. |
| `ledger_entry` | id, group_id, sequence, debtor_id, creditor_id, amount money, currency_code, source_type, source_id, effective_date, posted_at | amount > 0. debtor ≠ creditor. **UNIQUE**(source_type, source_id, debtor_id, creditor_id). **UNIQUE**(group_id, sequence). Append-only: no UPDATE or DELETE grants. |
| `payment` | id, group_id, payer_id, recipient_id, amount money, currency_code, payment_date, description NULL, recorded_by, recorded_at | amount > 0 (interim OD-07). payer ≠ recipient. Immutable. |
| `pair_balance` *(optional, OD-22)* | (group_id, low_user_id, high_user_id) PK, net money, version | low < high. `net = Σ ledger(low→high) − Σ ledger(high→low)`. Updated in the same transaction. Rebuildable. |

Extra constraint for payments: a `PAYMENT`-sourced `ledger_entry` has exactly one row per `source_id` (UNIQUE(source_type, source_id) restricted to PAYMENT, or the equivalent emulation).

### Notifications, idempotency and audit

| Table | Key columns | Constraints |
|---|---|---|
| `notification` | id, recipient_id, group_id, expense_id, type, created_at, read_at NULL | **UNIQUE**(recipient_id, expense_id, type) |
| `email_outbox_message` | id (also the provider idempotency key), kind, recipient_user_id NULL, recipient_email, notification_id NULL, template_key, params (no secrets except the verification link token), status, attempts, next_attempt_at, lease_until NULL, last_error_category NULL, created_at, sent_at NULL | **UNIQUE**(notification_id, kind) when notification_id is set. Index (status, next_attempt_at). |
| `processed_command` | command_id PK, user_id, command_type, request_fingerprint, result_ref, created_at | Retention is OD-26 |
| `audit_record` | id, actor_id, action, target_type, target_id, command_id NULL, at, detail (secret-free) | Append-only |

## 5. Idempotency keys

| Operation | Key | Backstop |
|---|---|---|
| Any mutating command | `processed_command.command_id` + fingerprint | PK |
| Expense approval posting | (EXPENSE, expense_id, debtor, creditor) | UNIQUE on ledger |
| Payment posting | (PAYMENT, payment_id) | UNIQUE on ledger |
| Review decision | (expense_id, level) | UNIQUE on review_record |
| Submission notice | (recipient, expense, type) | UNIQUE on notification |
| Email for a notice | (notification_id, kind) | UNIQUE on outbox |
| Provider send | outbox `id` | Provider-side, where supported |

## 6. Uniqueness summary

Account email. Active membership per (group, user). Pending invitation per (group, email). Review per (expense, level). Ledger posting per source and pair. One payment posting. Ledger sequence per group. Notification per (recipient, expense, type). Outbox row per (notification, kind). One receipt per expense.

## 7. Indexes for NFR-003 (ledger-derived first)

| Query | Access path |
|---|---|
| Group balances | `ledger_entry(group_id, debtor_id, creditor_id)` with grouped sums (at most 1,225 pairs) |
| Expense list or review queue | `expense(group_id, status, submitted_at)`, `reviewer_assignment(reviewer_id)` |
| Report by date | `expense(group_id, expense_date)`, `payment(group_id, payment_date)` |
| Member filter | `expense_share(participant_id, expense_id)`, `expense(payer_id)`, `payment(payer_id)`, `payment(recipient_id)` |
| My groups | `membership(user_id, removed_at)` |
| Unread notices | `notification(recipient_id, read_at, created_at)` |
| Outbox poll | `email_outbox_message(status, next_attempt_at)` |

Volume at the NFR-003 limit: 10,000 expenses per group, n participants each, and at most 10,000 × (n−1) expense ledger entries plus payments. The participant distribution is part of the OD-21 profile. It is not assumed here.

## 8. Required store capabilities (HD-11)

1. ACID transactions spanning several tables.
2. Unique constraints, including partial or filtered ones, or an equivalent emulation.
3. Row locking **or** compare-and-set on a version or sequence column.
4. An isolation level under which the races in design.md §9 are prevented. This must be proven by the concurrency tests (T-CON) on the selected store.
5. Exact decimal or 64-bit integer types.
6. Privilege separation, so the server account cannot UPDATE or DELETE `ledger_entry`, `payment`, `review_record` or `audit_record`.
7. Versioned schema migrations and backup and restore with tested recovery. Encryption at rest is subject to security review.

## 9. Full-product extensions (not MVP)

`review_requirement(group_id, level, reviewer_selector)` for multi-level review (OD-11). Device push tokens for mobile (OD-25). Web and mobile clients reuse the server API and need no model change for the core records.
